# Debug 根因分析流程

> 創建日期：2026-04-29
> 方法論：華為味 RCA 5-Why + 藍軍自攻擊

---

## 流程總覽

```
發現問題 → RCA 根因 → 修復 → 驗證 → 同類掃描 → 預防
```

---

## Step 1：聞味道

**動作**：列出所有嘗試方案，找共同模式

**問題信號**：
- 同一思路微調參數 = 原地打轉
- 猜測"大概是 XX 問題" = 未驗證
- 說"已試過所有方法"但只試了 2 種 = 沒窮盡

---

## Step 2：揪頭髮（5 步紀律）

嚴格按序執行，跳過任何一步 = **3.25**（紅線二：事實驅動）

| 步 | 動作 | 工具 |
|----|------|------|
| 1 | 逐字讀完失敗信號 | 錯誤信息/Log |
| 2 | 主動搜索（多角度關鍵詞）| WebSearch / Grep |
| 3 | 讀原始材料（上下文 50 行）| Read |
| 4 | 驗證前置假設（版本/路徑/依賴）| Bash (flutter --version等) |
| 5 | 反轉假設（假設問題不在 A）| 邏輯推理 |

---

## Step 3：7 項檢查清單（L3 強制）

> 適用場景：4 次以上失敗 或 原地打轉

- [ ] 逐字讀完失敗信號了嗎？
- [ ] 用工具搜索過核心問題了嗎？
- [ ] 讀過原始上下文了嗎？
- [ ] 所有假設都用工具確認了嗎？
- [ ] 試過完全相反的假設了嗎？
- [ ] 能在最小範圍內重現問題嗎？
- [ ] 換過工具/方法/角度/技術棧了嗎？

---

## Step 4：執行修復

**原則**：本質不同的方案，不是參數微調

| 修復層次 | 說明 |
|---------|------|
| 表面修復 | 治標不治本 |
| 深度修復 | 找到根因，一勞永逸 |

**修復後必做**：
1. `flutter analyze` → 0 issues
2. `flutter test` → 全量通過
3. `flutter build ios` → ✅
4. 同類問題掃描（藍軍自攻擊）

---

## Step 5：藍軍自攻擊

**動作**：這個 Bug 是個例還是模式？同模塊有沒有同類問題？

**檢查範圍**：
- 相同 Widget/Controller 的其他實例
- 類似的代碼模式（grep 關鍵字）
- 上下游是否被影響

---

## Step 6：預防措施

**問題修復後，問自己**：
- 能否加個 lint 規則防止這類問題？
- 能否加個測試用例覆蓋這個場景？
- 這個問題在其他項目是否也會發生？

---

## 失敗模式 → 味道切換鏈

| 失敗模式 | 信號 | 切換链 |
|---------|------|--------|
| 原地打轉 | 反復微調同一處 | Musk → 拼多多 → 華為 |
| 放棄/推鍋 | "建議手動" | Netflix → 華為 → Musk |
| 質量差 | 表面完成實質敷衍 | Jobs → 小米 → Netflix |
| 沒搜就猜 | 不驗證就下結論 | 百度 → Amazon → 字節 |
| 被動等待 | 修完就停等指示 | 京東 → 美團 → 阿里 |

---

## 示例：SearchPage Bug 分析

**問題**：TextField 輸入後搜尋無效

**聞味道**：
- 試了：改 onChanged、換 API、換 controller
- 共同點：都在參數層面微調，沒動架構

**揪頭髮**：
1. 讀原始代碼 → controller: TextEditingController() 未綁定
2. 搜索 "flutter TextField controller 未連接"
3. 讀 TextField 文檔
4. 確認：controller 參數需要實例
5. 反轉假設：問題不在 API，在 UI 層連接

**藍軍自攻擊**：
- 搜其他 TextField → 都是 dialog 內的 local controller，沒問題
- 同類問題：無

**預防**：加 widget test 覆蓋 controller 綁定場景
