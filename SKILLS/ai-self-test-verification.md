# AI 自測驗證 Skill v1.0

> 創建日期：2026-04-29
> 更新日期：2026-04-29
> 用途：每次 Bug 修復、功能實現後的標準化自測流程
> 適用範圍：所有 Flutter App 開發項目的交付驗證

---

## 一、核心原則

**底層邏輯**：測試通過 ≠ 功能完整實現。AI 自測是對照 PRD 逐項驗證功能是否真正落地。

| 原則 | 說明 |
|------|------|
| **先寫測試再寫代碼** | 測試用例是驗收標準的具體化 |
| **對照 PRD 逐項驗證** | 每個驗收標準都要有對應的驗證方式 |
| **同類問題掃描** | 修完 A 問題，檢查 B/C 同類問題 |
| **閉環交付** | Write→ls→wc→Read 機械約束，嚴禁虛假交付 |

## 三、執行命令標準

```bash
# 1. 代碼分析
flutter analyze

# 2. 單元測試 + Widget 測試
flutter test

# 3. iOS Build 驗證
flutter build ios --simulator --no-codesign

# 4. App 安裝 + 啟動
xcrun simctl uninstall booted com.{bundleId}
xcrun simctl install booted build/ios/iphonesimulator/Runner.app
xcrun simctl launch booted com.{bundleId}

# 5. 截圖驗證（如有 UI 變更）
xcrun simctl io booted screenshot /tmp/{feature}_verified.png
```

## 四、PRD 對照驗證法

### 4.1 讀取 PRD 驗收標準

```bash
# 讀取 PRD 文件
cat docs/PRD/vX.Y_{NAME}.md
```

### 4.2 逐項對照清單

| # | PRD 驗收標準 | 當前狀態 | 驗證方式 | 結論 |
|---|-------------|---------|---------|------|
| 1 | 標準描述 | ✅/❌/⚠️ | 代碼審查/截圖 | 通過/不通過 |
| 2 | 標準描述 | ✅/❌/⚠️ | 代碼審查/截圖 | 通過/不通過 |

### 4.3 藍軍自攻擊清單

修復完成後，主動檢查：
- [ ] 同模塊是否有類似問題？
- [ ] 上下游組件是否受影響？
- [ ] 邊界條件是否處理？
- [ ] 異常輸入是否會崩潰？

## 五、BUG 修復自測流程

### 5.1 Debug Flow（型號路由）

| 失敗次數 | 檢測信號 | 方法論路由 |
|---------|---------|-----------|
| 2 次 | 參數微調迴圈 | ⬛ Musk（質疑需求+刪除）→ 🟣 拼多多（砍中間環節）→ 🔴 華為（藍軍反向攻擊）|
| 3 次 | 搜索+讀碼+假設 | ⚫ 百度（搜索第一）→ 🔶 Amazon（Dive Deep）→ 🟡 字節（數據驅動）|
| 4 次 | L3 強制 | 完成 7 項檢查清單 |
| 5+ 次 | 畢業警告 | 拼命模式 + 結構化失敗報告 |

### 5.2 7 項檢查清單（L3+ 強制）

- [ ] 逐字读完失败信号了吗？
- [ ] 用工具搜索过核心问题了吗？
- [ ] 读过失败位置的原始上下文了吗？
- [ ] 所有假设都用工具确认了吗？
- [ ] 试过完全相反的假设吗？
- [ ] 能在最小范围内复现问题吗？
- [ ] 换过工具/方法/角度/技术栈吗？

### 5.3 Bug 修復自測清單

## 六、交付前 SSOT 驗證（防止虛假交付）

> **底層邏輯**：口說無憑，工具驗證才是事實。

### 6.1 機械約束（強制執行）

```
1. Write tool → 文件寫入磁盤
2. Bash ls → 確認文件存在
3. Bash wc -c → 確認文件大小 > 100 bytes
4. Read tool → 抽檢前 3 行確認非空
5. 才能回覆用戶"已交付"
```

### 6.2 反模式（禁止）

```
❌ 只說"已生成"
❌ 只說"已交付"
❌ 用想像的交付框代替真實工具驗證
❌ 看到用戶失望就跳過驗證
```

### 6.3 正確姿勢

```bash
# 文檔交付
echo "=== SSOT 驗證 ===" && \
ls -la docs/PRD/vX.Y.md && \
wc -c docs/PRD/vX.Y.md && \
head -3 docs/PRD/vX.Y.md

# 代碼交付
flutter analyze && flutter test && \
ls build/ios/iphonesimulator/Runner.app
```

## 八、Owner 意識四問

每次交付前默念：
1. **這個問題的根因是什麼？** 不是"怎麼改能過"，是"為什麼會出這個問題"
2. **還有誰會被影響？** 改了 A，B 和 C 會不會炸？上下游對齊了嗎？
3. **下次怎麼防止？** 修完 bug 不是終點，能不能加個檢查讓這類問題不再發生？
4. **數據在哪？** 你的判斷有數據支撐嗎？還是拍腦袋？
